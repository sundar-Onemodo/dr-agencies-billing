1. Executive Summary & System Architecture

D R Agencies Billing App is an enterprise-grade point-of-sale, GST billing, and inventory management mobile application developed for wholesale distributors and retail agencies. It eliminates manual billing errors, automates stock deduction, tracks customer credit ledgers, and connects wirelessly with portable Bluetooth thermal receipt printers.

Frontend Architecture
  • Expo Router v5: File-based routing with deep-linking support.
  • Redux Toolkit (RTK): Centralized store management with asynchronous thunks.
  • AsyncStorage: Local persistence for offline state and token caching.
  • React Native Reanimated: Smooth 60fps animations and micro-interactions.
Backend Architecture
  • Express.js REST API: Lightweight microservices controller layer.
  • Supabase PostgreSQL: Scalable database with Row-Level Security (RLS).
  • Postgres RPC: Atomic server-side stored procedures for inventory operations.
  • JWT Authentication: Stateless bearer token verification.

2. Authentication & User Session Flow

The authentication system ensures secure multi-tenant isolation. All inventory items, customer lists, and invoice records are bound to the authenticated user's unique user_id.

1
Login Screen (app/login.tsx)
Supports login via registered email or 10-digit mobile number with password verification. Form validation checks email formatting and password strength in real time.
2
JWT Token Exchange & Persistence
Upon successful authentication, the backend issues a signed JWT token. The app saves the token into device AsyncStorage and initializes the global Redux auth slice.
3
Auto-Hydration & Persistent Auth Guard
When the app is relaunched, initializeAuth() validates the cached token and immediately redirects authenticated users to the main Dashboard, bypassing login.

4. Quick Bill & Invoice Creation Flow

The Quick Bill screen (app/(tabs)/create-bill.tsx) is engineered for high-speed counter checkout.

1. Customer Information & Auto-Fill

Typing in the customer name field opens an autocomplete dropdown from the Customer Directory. Selecting a customer auto-populates address, phone, GSTIN, and State. If a new customer is typed, a "+ Save to Directory" button appears to persist their details with a single tap.

2. Product Entry & Live Stock Badge

Searching a product dynamically displays its current store stock. When selected, the unit price is filled automatically. The quantity input supports decimal numbers (e.g. 2.5 kg) for weight-based sales.

3. Dynamic GST & Payment Configurations

The GST toggle automatically computes CGST (50%) and SGST (50%) according to each product's configured tax rate (0%, 5%, 12%, 18%, 28%). Grand totals are rounded off cleanly. Payment status can be toggled to Paid with method selection (Cash, GPay, PhonePe, Paytm).

5. Combined Stock Allocation Algorithm

In a dynamic retail environment, editing an existing invoice requires a specialized mathematical formula. The system must account for stock that was already allocated to the current bill plus remaining stock in the physical store.

Store Stock
4.0 kg

Max Allowed
5.0 kg

Mathematical Formulation

TotalStockPool      = DB_Stock_Qty + Original_Billed_Qty
RemainingStoreStock = MAX(0, TotalStockPool - Current_Active_Bill_Qty)
MaxAllowedForItem   = TotalStockPool - Other_Items_In_Bill_Qty
Concrete Scenario Walkthrough
  1. Initial State: Product A has 5 kg in store inventory.
  2. First Bill Created: Customer purchases 1 kg. Backend deducts 1 kg; DB stock becomes 4 kg.
  3. Invoice Edit Session Opened: The bill loads with 1 kg. Total available pool is 4 kg + 1 kg = 5 kg.
  4. User Increments to 3 kg: Stepper allows increment up to 5 kg. 3 kg <= 5 kg is valid.
  5. Save & Sync: Backend restores 1 kg (DB=5 kg), validates 3 kg <= 5 kg, deducts 3 kg. Remaining DB stock becomes 2 kg!

6. Duplicate Line Item Prevention System

Allowing duplicate rows for the same product in a single bill creates quantity calculation mismatches and invoice ambiguity. A multi-layered protection mechanism is active in create-bill.tsx:

1. Visual Dropdown Highlighting

Products already present in the active bill appear in the search dropdown with a distinctive gold highlight and a badge: ✓ Added in invoice (X kg) • Tap to edit below.

2. Interception & Guidance Modal

If the user attempts to select or click "+ Add Item" for an already added product, the system intercepts the action and displays an informative alert: "Product is already in this invoice. Please edit its quantity from the Items List below."

7. Invoice Editing & Atomic Stock Deltas

The invoice update workflow utilizes database-level transactions to ensure stock counts are never corrupted or over-deducted during multi-user edits.

1
Restore Previous Stock (Reversion)
The backend controller fetches the previous line items of the invoice and calls decrement_product_stock(p_id, -old_qty) to restore inventory temporarily.
2
Aggregate Validation
The system sums total requested quantities per product ID and validates against the newly restored store stock. If requested quantity exceeds stock, the operation rolls back and returns a 400 error.
3
Deduct New Stock & Replace Line Items
The backend deducts the new quantities atomically, replaces the rows in bill_items, updates bill totals, and records stock movement logs with reference UPDATE-BILL-<inv_no>.

11. Printing Hardware & PDF Generation

The application features a hybrid printing pipeline supporting both wireless portable Bluetooth thermal printers and standard A4 office printers.

Postgres Atomic Stock RPC Function (schema.sql)
CREATE OR REPLACE FUNCTION decrement_product_stock(p_id BIGINT, p_qty NUMERIC, p_user_id UUID)
RETURNS BOOLEAN AS $$
DECLARE v_current_stock NUMERIC;
BEGIN
  SELECT stock_qty INTO v_current_stock FROM products WHERE id = p_id AND user_id = p_user_id FOR UPDATE;
  IF v_current_stock IS NULL OR (p_qty > 0 AND v_current_stock < p_qty) THEN
    RETURN FALSE;
  END IF;
  UPDATE products SET stock_qty = stock_qty - p_qty, updated_at = NOW() WHERE id = p_id AND user_id = p_user_id;
  RETURN TRUE;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
